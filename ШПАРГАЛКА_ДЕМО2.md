## Новые юниты Демо 2

### 1. Хилер (Healer)

**Что делает:** лечит рандомного союзника в пределах Range.

**Наследование:**
```csharp
public class Healer : Unit, ISpecialAbility, ICanBeHealed
```
- `Unit` — базовые характеристики (HP, ATK, DEF)
- `ISpecialAbility` — имеет Range и Power (сила лечения)
- `ICanBeHealed` — другой хилер может лечить этого

**Кого можно лечить (ICanBeHealed):**
| Юнит | ICanBeHealed | Почему |
|------|-------------|--------|
| LightInfantry | ✅ | Обычный боец |
| Archer | ✅ | Обычный боец |
| Healer | ✅ | Хилеры лечат друг друга |
| HeavyInfantry | ❌ | Слишком бронированный |
| Wizard | ❌ | Маг не лечится |
| GulyayGorod | ❌ | Внешний объект, нет интерфейса |

**Кого НЕ лечит:** себя (проверка `j == healerIndex`).

**Формула лечения:**
```csharp
public int UseAbility(Unit target)
{
    // HP не может расти выше MaxHealth
    int healAmount = Math.Min(Power, target.MaxHealth - target.Health);
    target.Health += healAmount;
    return healAmount;
}
```

**Как выбирает цель (Battlefield.ProcessHealer):**
```csharp
// Собираем кандидатов: живые, ICanBeHealed, не сам хилер, HP < MaxHP, в пределах Range
for (int j = 0; j < allies.Units.Count; j++)
{
    if (j == healerIndex) continue;                     // не лечит себя
    if (!allies.Units[j].IsAlive) continue;
    if (allies.Units[j] is not ICanBeHealed) continue;  // только ICanBeHealed
    if (allies.Units[j].Health >= allies.Units[j].MaxHealth) continue;

    // Проверка дальности
    int distance = Math.Abs(j - healerIndex);
    if (distance > healer.Range) continue;

    candidates.Add(allies.Units[j]);
}
// Рандомный выбор из кандидатов
var target = candidates[Rng.Next(candidates.Count)];
```

**Пример вывода:**
```
  A1:Хилер#3 (поз. 3, дальность 3) -> лечит A1:Лучник#2
    Восстановлено: +18 HP
    A1:Лучник#2: 37 -> 55 HP
```

**Базовые характеристики:**
| Параметр | База | Разброс |
|----------|------|---------|
| Damage | 5 | ±2 |
| Defense | 2 | ±1 |
| Health | 50 | ±10 |
| Range | 3 | ±1 |
| Power (лечение) | 20 | ±5 |

### 2. Маг (Wizard)

**Что делает:** с маленькой вероятностью клонирует союзника и ставит клон перед собой.

**Наследование:**
```csharp
public class Wizard : Unit, ISpecialAbility
```
- НЕ реализует `ICanBeHealed` — нельзя лечить
- НЕ реализует `ICanBeCloned` — нельзя клонировать мага

**Кого можно клонировать (ICanBeCloned):**
| Юнит | ICanBeCloned | Почему |
|------|-------------|--------|
| LightInfantry | ✅ | Простой боец |
| Archer | ✅ | Простой боец |
| HeavyInfantry | ❌ | Слишком мощный |
| Healer | ❌ | Баланс |
| Wizard | ❌ | Нельзя клонировать мага |
| GulyayGorod | ❌ | Внешний объект |

**Интерфейс ICanBeCloned:**
```csharp
public interface ICanBeCloned
{
    Unit Clone();  // создаёт копию с текущими характеристиками
}
```

**Реализация Clone() в LightInfantry:**
```csharp
public Unit Clone()
{
    return new LightInfantry(Name + "*", Damage, Defense, Health) { MaxHealth = MaxHealth };
}
```
Имя клона = оригинал + `*` (A1:Лёгкий#3 → A1:Лёгкий#3*)

**Как работает клонирование (Battlefield.ProcessWizard):**
```csharp
// 1. Проверяем шанс (CloneChance%)
if (Rng.Next(100) >= wizard.CloneChance)
{
    Logger.CloneFailed(wizard, position);
    return;
}

// 2. Ищем кандидатов: живые, ICanBeCloned, в пределах Range
int distance = Math.Abs(j - wizardIndex);
if (distance > wizard.Range) continue;

// 3. Рандомный выбор + вставка клона перед магом
var clone = ((ICanBeCloned)original).Clone();
allies.Units.Insert(wizardIndex, clone);  // клон встаёт перед магом
```

**Пример вывода:**
```
  A1:Маг#4 (поз. 4) -> клонировал A1:Лёгкий#3!
    Создан клон: A1:Лёгкий#3* [HP: 78/78, ATK: 28, DEF: 6]

  A2:Маг#2 (поз. 2) -- клонирование не сработало
```

**Базовые характеристики:**
| Параметр | База | Разброс |
|----------|------|---------|
| Damage | 6 | ±2 |
| Defense | 2 | ±1 |
| Health | 45 | ±10 |
| Range | 3 | ±1 |
| CloneChance | 30% | ±10% |

### 3. Гуляй-город (GulyayGorodAdapter) — паттерн Adapter

**Что делает:** живая стена. Не атакует, огромная защита и HP. Впитывает урон, пока за ним работают лучники и маги.

**Зачем адаптер?** Гуляй-город поставляется как готовая DLL (`MedievalRussia.dll`) с чужим API:

```csharp
// Внешний класс из DLL (декомпилированный)
namespace MedievalRussia;
public class GulyayGorod(int Health, int Defence)
{
    public bool HasDestroyed => Health <= 0;
    public int Defence => Defence;
    public int GetHealth() { ... }
    public void ReduceHealth(int Count) { Health -= Count; }
}
```

У него нет `Name`, `Damage`, `Attack()`, `IsAlive` — ничего из нашего `Unit`. Адаптер переводит чужой API в наш:

```csharp
public class GulyayGorodAdapter : Unit
{
    private GulyayGorod _inner;  // оригинальный объект из DLL

    public GulyayGorodAdapter(string name, int defense, int health)
    {
        Name = name;
        Damage = 0;   // не атакует
        Defense = defense;
        Health = health;
        MaxHealth = health;
        _inner = new GulyayGorod(health, defense);
    }
}
```

**Схема паттерна Adapter:**
```
Battlefield → работает с Unit
                  ↑
        GulyayGorodAdapter : Unit    ← наш адаптер
                  |
        GulyayGorod (из DLL)         ← чужой класс
```

**Что НЕ делает:**
- Не атакует (Damage = 0, в бою наносит 1 мин. урон)
- Не лечится (нет ICanBeHealed)
- Не клонируется (нет ICanBeCloned)
- Нет спецспособности (нет ISpecialAbility)
- При настройке нельзя менять урон (только Защита и HP)

**Пример вывода:**
```
    5. A1:ГуляйГород#5 [HP: 210/210, DEF: 33, ATK: нет]
```

### 4. Щит (UnitProxy) — паттерн Proxy

**Что делает:** оборачивает любого юнита, добавляя барьер. Пока щит > 0, урон идёт в щит. Когда щит разрушен — урон идёт в HP.

```csharp
public class UnitProxy : Unit
{
    public int Shield { get; set; }

    // Оборачивает существующего юнита
    public UnitProxy(Unit inner, int shield)
    {
        Name = inner.Name + " [щит]";
        Damage = inner.Damage;    // копируем все характеристики
        Defense = inner.Defense;
        Health = inner.Health;
        MaxHealth = inner.MaxHealth;
        Shield = shield;
    }

    // Перехватывает урон
    public int AbsorbDamage(int incomingDamage)
    {
        int absorbed = Math.Min(Shield, incomingDamage);
        Shield -= absorbed;
        return absorbed;
    }
}
```

**Как работает в бою (Unit.Attack):**
```csharp
public int Attack(Unit target)
{
    int actualDamage = Math.Max(Damage - target.Defense, 1);

    // Паттерн Proxy: щит перехватывает урон
    if (target is UnitProxy proxy && proxy.Shield > 0)
    {
        int absorbed = proxy.AbsorbDamage(actualDamage);
        int remaining = actualDamage - absorbed;
        target.Health = Math.Max(target.Health - remaining, 0);
    }
    else
    {
        target.Health = Math.Max(target.Health - actualDamage, 0);
    }
    return actualDamage;
}
```

**Как получить щит:**
- Случайные армии: 20% шанс автоматически
- Ручное создание: вопрос "Добавить щит? [y/n]"

**Пример вывода:**
```
  A2:Лёгкий#1 -> атакует -> A1:Тяжёлый#1 [щит]
    Урон: 30 - 17 (защита) = 13
    A1:Тяжёлый#1 [щит]: 150 -> 150 HP
    Щит поглотил: 13 урона (осталось щита: 29)

  ...позже:
    Щит поглотил: 5 урона (осталось щита: 0)
    *** Щит A1:Тяжёлый#1 [щит] разрушен! ***

  Вывод в армии:
    1. A1:Тяжёлый#1 [щит] [HP: 150/150, ATK: 22, DEF: 17, SHIELD: 29]
    ...после разрушения:
    1. A1:Тяжёлый#1 [щит] [HP: 130/150, ATK: 22, DEF: 17, щит разрушен]
```

### 5. Звуковой прокси (SoundLoggerProxy) — паттерн Proxy для логгера

**Что делает:** оборачивает `BattleLog` и добавляет звуковой сигнал при гибели юнита.

```csharp
public class SoundLoggerProxy : IBattleLogger
{
    private readonly IBattleLogger _inner;

    // Все методы делегируются реальному логгеру
    public void TurnHeader(int turn) => _inner.TurnHeader(turn);
    // ... остальные методы аналогично

    // Proxy-поведение: при смерти — звук + делегирование
    public void UnitDied(Unit unit, string armyName)
    {
        _inner.UnitDied(unit, armyName);
        try { Console.Beep(300, 150); } catch { }
    }
}
```

**Подключение в Program.cs (Dependency Injection + Proxy):**
```csharp
IBattleLogger logger = new SoundLoggerProxy(new BattleLog());
var bf = new Battlefield(logger);
```

**Цепочка:** `Battlefield` → `SoundLoggerProxy` → `BattleLog` → консоль

## Паттерны проектирования

### Singleton — ArmyFactory
```csharp
public class ArmyFactory
{
    private static ArmyFactory? _instance;
    public static ArmyFactory Instance => _instance ??= new ArmyFactory(new RandomUnitFactory());

    private ArmyFactory(IUnitFactory unitFactory) { ... }
}

// Использование:
var factory = ArmyFactory.Instance;  // всегда один экземпляр
```
**Зачем:** фабрика армий одна на всю игру. `private` конструктор запрещает создание извне.

### Абстрактная фабрика — IUnitFactory
```csharp
public interface IUnitFactory
{
    Unit CreateHeavyInfantry(int number, string tag);
    Unit CreateLightInfantry(int number, string tag);
    Unit CreateArcher(int number, string tag);
    Unit CreateHealer(int number, string tag);
    Unit CreateWizard(int number, string tag);
    Unit CreateGulyayGorod(int number, string tag);
    Unit CreateRandom(int number, string tag);  // фабричный метод
}
```
**Зачем:** можно создать другую реализацию (например, `BalancedUnitFactory`) без изменения `ArmyFactory`.

### Конкретная фабрика — RandomUnitFactory
```csharp
public class RandomUnitFactory : IUnitFactory
{
    public Unit CreateHeavyInfantry(int number, string tag)
    {
        return new HeavyInfantry(
            name: MakeName("Тяжёлый", number, tag),
            damage: Vary(HeavyInfantry.BaseDamage, 4),  // рандомизация
            defense: Vary(HeavyInfantry.BaseDefense, 3),
            health: Vary(HeavyInfantry.BaseHealth, 20));
    }
    // ... остальные юниты аналогично
}
```

### Фабричный метод — CreateRandom
```csharp
public Unit CreateRandom(int number, string tag)
{
    return _rng.Next(6) switch
    {
        0 => CreateHeavyInfantry(number, tag),
        1 => CreateLightInfantry(number, tag),
        2 => CreateArcher(number, tag),
        3 => CreateHealer(number, tag),
        4 => CreateWizard(number, tag),
        _ => CreateGulyayGorod(number, tag)
    };
}
```
**Зачем:** вызывающий код не знает конкретный тип юнита — фабричный метод решает.

### Adapter — GulyayGorodAdapter
Описан выше. Оборачивает чужой `GulyayGorod` из DLL в наш `Unit`.

### Proxy — UnitProxy и SoundLoggerProxy
Два применения:
1. `UnitProxy` — перехватывает урон (щит перед HP)
2. `SoundLoggerProxy` — добавляет звук к логгеру

## Создание армии по бюджету

**Флоу:**
```
Бюджет на каждую армию (например, 500): 600

--- Армия 1 (бюджет: 600) ---
1. Случайная армия        ← автоматически набирает юнитов в рамках 600
2. Создать вручную         ← покупаешь юнитов, видя цены и остаток
```

**При ручной покупке:**
```
Примерные цены юнитов:
  1. Тяжёлый пехотинец  ~213
  2. Лёгкий пехотинец   ~148
  3. Лучник             ~81
  4. Хилер              ~63
  5. Маг                ~60
  6. Гуляй-город        ~245

  Осталось бюджета: 600
  Юнит 1: > 1
  Создан: A2:Тяжёлый#1 [HP: 148/148, ATK: 22, DEF: 14] (цена: 210)
  Настроить характеристики? [y/n]: n
  Добавить щит? [y/n]: n
  Куплен: A2:Тяжёлый#1 (цена: 210)

  Осталось бюджета: 390
  Юнит 2: > 6
  Создан: A2:ГуляйГород#2 [HP: 211/211, DEF: 35, ATK: нет] (цена: 264)
  Настроить характеристики? [y/n]: y
    Защита [35]: 40      ← только защита и HP для Гуляй-города
    HP [211]: 200
  Не хватает бюджета! Стоит 260, осталось 390   ← если дорого
  > 0                    ← завершить набор
```

**Формула цены:**
```
Price = Damage × 2 + ⌈Defense × 1.5⌉ + MaxHealth
```
Примеры:
| Юнит | ATK | DEF | HP | Цена |
|------|-----|-----|----|------|
| Тяжёлый (база) | 20 | 15 | 150 | 20×2 + 23 + 150 = **213** |
| Лёгкий (база) | 30 | 5 | 80 | 30×2 + 8 + 80 = **148** |
| Лучник (база) | 8 | 3 | 60 | 8×2 + 5 + 60 = **81** |
| Хилер (база) | 5 | 2 | 50 | 5×2 + 3 + 50 = **63** |
| Маг (база) | 6 | 2 | 45 | 6×2 + 3 + 45 = **60** |
| Гуляй-город (база) | 0 | 30 | 200 | 0×2 + 45 + 200 = **245** |

## SOLID — что добавилось в Демо 2

| Принцип | Как реализован |
|---------|---------------|
| **S** (Single Responsibility) | Каждый юнит — одна роль. Хилер лечит, маг клонирует. Не смешиваются. |
| **O** (Open/Closed) | Добавили 4 новых юнита БЕЗ изменения Battlefield (только новые методы ProcessHealer, ProcessWizard). Лучник и ближний бой — без изменений. |
| **L** (Liskov Substitution) | Все новые юниты работают как Unit. List<Unit> хранит и Heavy, и Healer, и GulyayGorod. |
| **I** (Interface Segregation) | ICanBeHealed и ICanBeCloned — отдельные маленькие интерфейсы. Heavy не заставляют реализовывать Clone(). |
| **D** (Dependency Inversion) | Battlefield зависит от IBattleLogger, не от BattleLog. ArmyFactory зависит от IUnitFactory, не от RandomUnitFactory. |

## Сохранение/загрузка

**Сохранение с именем:**
```
> 4
Имя сохранения (Enter = battle_save): Мой_бой
  Игра сохранена: .../saves/Мой_бой.json
```

**Загрузка со списком:**
```
Доступные сохранения:
  1. battle_save
  2. Мой_бой
  0. Назад в главное меню

Номер или имя файла: 2
  Игра загружена: .../saves/Мой_бой.json (ход 5)
```

**JSON-сериализация новых юнитов:**
```csharp
// В Unit.cs — дискриминаторы для всех типов
[JsonDerivedType(typeof(HeavyInfantry), "heavy")]
[JsonDerivedType(typeof(LightInfantry), "light")]
[JsonDerivedType(typeof(Archer), "archer")]
[JsonDerivedType(typeof(Healer), "healer")]
[JsonDerivedType(typeof(Wizard), "wizard")]
[JsonDerivedType(typeof(GulyayGorodAdapter), "gulyay")]
[JsonDerivedType(typeof(UnitProxy), "proxy")]
```
